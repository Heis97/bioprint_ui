# Биопринт 1.0 — пульт управления биопринтером (bioprint_ui)

Сенсорный интерфейс для экрана 17" 1920×1080. Работает с текущими версиями шлюза
`tcp_to_udp` (ветка `test_sech`) и прошивки `Marlin-2.1.2.5-sech2` (19.10.2026):
команды сверены с `String_line4.py` и кодом шлюза и собраны в `protocol.py`.
Что менялось при актуализациях — `CHANGES.md`, как пульт работает со шлюзом — `ANALYSIS.md`.

## Запуск

При запуске пульт:
1. запускает шлюз `tcp_to_udp.exe` (если он ещё не работает) — см. «Шлюз»;
2. просит пароль — см. «Пароль»;
3. открывает окно «Подключение к принтеру» и ждёт шлюз и обе платы; окно закрывается
   само, когда всё на связи, или по кнопке «Продолжить без ожидания».

### Из Visual Studio Code

1. Откройте в VS Code папку репозитория oct_ui (File → Open Folder).
2. Откройте файл `bioprint_ui/start.py` и нажмите **F5**.

Виртуальное окружение не нужно: при первом запуске недостающие PyQt5, opencv-python и numpy
ставятся в системный Python автоматически. Режим (демо, полный экран) меняется константами
`DEMO` и `FULLSCREEN` в начале `start.py`. В меню запуска (Ctrl+Shift+D) также есть
готовые варианты «Пульт биопринтера» и «Пульт биопринтера — демо».

### С рабочего стола

Два способа, оба создают на рабочем столе ярлык **«Биопринт»** со значком программы;
запуск — на весь экран, выход — кнопкой «⏻ Выход».

**1. Bioprint.exe (рекомендуется для ПК принтера).** Двойной щелчок по `build_exe.bat`:
ставит библиотеки и PyInstaller, собирает `dist\Bioprint\Bioprint.exe` по `bioprint.spec`
и создаёт ярлык. Папку `dist\Bioprint` можно скопировать на ПК без Python; ярлык там —
`make_shortcut.ps1 -Mode exe -Exe путь\Bioprint.exe` (или вручную «Отправить → Рабочий стол»).
Настройки (`settings.json`), снимки камер и журнал ошибок `bioprint_error.log` лежат рядом с exe.
После правок кода exe нужно собрать заново.

**2. Без сборки.** Двойной щелчок по `shortcut_python.bat`: ярлык запускает `start.py`
через `pythonw` (без окна консоли). Правки кода видны сразу, но на ПК нужен Python с
PyQt5 — запустите один раз из VS Code (F5), чтобы библиотеки установились.

Ключи ярлыка: `--window` — в окне, `--demo` — симулятор. Отдельный ярлык для демо:
`powershell -ExecutionPolicy Bypass -File make_shortcut.ps1 -Mode exe -Demo`.

### Из командной строки

```
python bioprint_ui/start.py
python -m bioprint_ui            # на весь экран, подключение к 127.0.0.1:62000 (шлюз serv/tcp_to_udp.exe)
python -m bioprint_ui --demo     # встроенный симулятор, без железа
python -m bioprint_ui --window   # в окне 1920×1080
```

Запускать из корня репозитория oct_ui (папка `bioprint_ui` лежит рядом с `String_line4.py`).
Адрес, порт, демо-режим и шлюз меняются на экране «Калибровка» и сохраняются в `settings.json`.

## Шлюз

Путь к `tcp_to_udp.exe` — «Калибровка → Подключение → Шлюз» (по умолчанию `serv\tcp_to_udp.exe`
в папке oct_ui; для exe-версии — папка `serv` рядом с папкой `Bioprint`). Там же:
«Запускать при старте» (да/нет) и «Перезапустить шлюз».
- Шлюз запускается, только если адрес подключения — этот компьютер (127.0.0.1) и порт ещё
  не занят: запущенный вручную шлюз пульт не трогает.
- Рабочая папка шлюза — его собственная (там `settings_printer.json`); у шлюза своё окно
  консоли с журналом.
- При выходе из пульта запущенный им шлюз закрывается (`gateway_stop_on_exit` в settings.json).
- Сколько ждать связи — `config.GATEWAY_WAIT_S` (40 с).

## Пароль

Пароль спрашивается при каждом запуске. Ввод — экранной цифровой клавиатурой или обычной
(можно и буквы).
- **Где хранится:** `settings.json` рядом с программой, поле `"password"` — только хэш
  PBKDF2-SHA256 со случайной солью (200 000 итераций); сам пароль нигде не записан.
- **Первый запуск:** окно «Задайте пароль» (не короче 4 символов, дважды).
- **Сменить:** «Консоль → Интерфейс → 🔒 Сменить пароль» (нужен текущий).
- **Забыли:** закройте программу, удалите из `settings.json` строку `"password": {…}` —
  при следующем запуске программа попросит задать новый.

| Ручное | перемещение XYZ удержанием или **на шаг** (0,1–10 мм), **скорость перемещения**, ноль ручной СК, координаты текущей СК / машины / инструмента, выдавливание, «Задать как текущий» под каждой головкой |
| Периферия | подача подложек, термостол, **пневматика** (насос, стол, крышка, сброс), 2 гомогенизатора, 2 манипулятора, **освещение**, **лазерная система** (замкнут/разомкнут каждый луч) |
| Калибровка | калибровка стола по 3 точкам, Home-тест, калибровка дельты, загрузка настроек, текущий инструмент и смена головки, подключение и шлюз |
| Камеры | приём JPEG-кадров по UDP (как `CameraThreadUDP`): для каждой камеры — IP источника и порт приёма (по умолчанию 192.168.1.81, порты 5000–5002), адрес интерфейса приёма; состояние; экспозиция (M590), снимки в `snapshots` |

Вверху на каждом экране две кнопки:
- **Стоп** — остановить программу печати и все перемещения (`main M700`: шлюз останавливает
  обе платы и пропускает остаток программы);
- **АВАРИЙНЫЙ СТОП** — то же, плюс `M589 S` напрямую на обе платы и выключение нагрева стола.

Внизу боковой панели: **ⓘ О программе** — название ПО (Биопринт) и версия (1.0);
**☾/☀** — светлая/тёмная тема (также в «Консоль → Интерфейс»; выбор сохраняется),
**⏻ Выход** — закрыть программу или выключить компьютер (Windows: `shutdown /s /t 0`,
Linux: `systemctl poweroff`). Если идёт печать, она будет остановлена; при выключении ПК
выключается нагрев стола.

## G-код

Программа уходит в шлюз **без изменений** — убираются только комментарии (`; …`, `( … )`)
и пустые строки. Разбирает её сам шлюз. Что он понимает (подробно — `gcode.py`):
G0/G1, G90/G91, M82/M83, G92, G4, G28, M140/M190, M106/M107, **T<n>** (смена головки;
с автокалибровкой — затем калибровка сопла лазерами), **G54 X<i>** (подложка i).
Остальное, в том числе дуги G2/G3, шлюз пропускает.

Превью, прогресс и оценка времени повторяют разбор шлюза, а не стандарт G-кода, — чтобы
показывать то, что сделает принтер. Пульт предупреждает (экран «Печать», кнопка «G-код»):
- после T и G54 шлюз считает E с нуля — если E в файле продолжает расти, первый отрезок
  выдавит накопленное; после T E нужно начинать с 0, а в первом переходе писать E явно;
- G91: смещение прибавляется столько раз, сколько слов в строке;
- `G4 P500` шлюз превращает в паузу 5 с (склеивает числа) — пишите `G4 S`;
- дуги G2/G3, строки в нижнем регистре и с номерами N… шлюз пропускает.

Если программа начинается с T головки, которая уже на сопле, шлюз отдаёт её в манипулятор
и падает. Пульт перед стартом предлагает не отправлять эту строку.

Перед стартом пульт, как String_line4, отправляет флаги: автокалибровка (`M641`), подъём
крышки (`M643`), а также коэффициенты скорости (`M618`) и подачи (`M617`).

## Скорость и подача

«Печать → Скорость и подача», 10–340 %, шаг 5 % (как ползунки vel_koef / e_koef в
String_line4). Действуют на ходу: шлюз пересчитывает время кадров при отправке на плату.
Оценка «осталось» = модельное оставшееся время ÷ (скорость / 100) и пересчитывается сразу.
Значения сохраняются и отправляются шлюзу при каждом подключении.

## Системы координат

Шлюз присылает в каждой строке `st1` три набора координат и текущую систему:
- **Текущая СК** — в которой шлюз сейчас двигает (в ней же печатается программа);
- **Инструмент** — в системе печати: MANUAL (ноль оператора) или AUTO (калибровка);
- **Машина** — координаты принтера.
Системы: MANUAL «Ручная» — ноль задаёт кнопка «Установить 0 здесь» (свой у каждой головки);
AUTO «Авто» — ноль по калибровке сопла и подложке G54; INTERNAL «Машинная» — во время смены
головки; CURRENT «Текущая» — от точки, где стояло сопло (ручное перемещение).
Галка «Автокалибровка» на «Печати» выбирает MANUAL или AUTO (`M641`).

## Ручное перемещение

«Пока держишь» — `M611` (шлюз ведёт сопло, пока кнопка нажата). «На шаг» — короткая
программа в текущей СК: `M640 2`, `G1 X<шаг>`, `M597 0` — сопло сдвигается ровно на шаг.
Скорость — `M610` (0,1–15 мм/с, как ползунок jog_vel). Режим, шаг и скорость общие для
«Ручного» и «Калибровки» и сохраняются.

## Генератор

**Подложки и G54.** Программа начинается с `G54 X<i>`: X/Y центра у всех подложек общие
(ноль — центр подложки на дне), меняется Z. Номера i — `config.G54_INDEX`
(по умолчанию: Петри 35/60/90 — 0/1/2, планшеты 6/12/24/48/96 — 3…7); сдвиги — в
`settings_printer.json` шлюза (`offset_plate_x/y/z[i]`). В 3D видны стенки чашки или
корпус планшета с лунками; выбранные лунки выделены.

**STL-модель.** «Открыть STL…» (двоичный и текстовый); масштаб — один множитель на все оси:
в % или «Наибольший размер» в мм, кнопки 50/100/200 % и «Вписать в лунку»; периметров (0–10),
шаг заполнения, углы слоёв (0/90 — сетка). Модель ставится центром в центр лунки, низом на дно.
Слой режется по середине высоты; периметры — эквидистанты контура на (k + ½)·Ø сопла,
заполнение — линии с заданным шагом внутри периметров. Растровый метод (точность ~0,02–0,05 мм)
устойчив к отверстиям и узким местам. Нужен opencv-python.

**Головки.** «Текущая» — без T. «Одна» — T выбранной головки в начале. «По лункам» —
выберите головку-кисть и касайтесь лунок (цвет лунки = головка); лунки печатаются группами,
каждая головка берётся один раз. «По слоям» — порядок «головка × слоёв», повторяется
до последнего слоя; печать идёт слой за слоем во всех лунках. После каждой T генератор
начинает E с 0 и пишет E в первом переходе — так, как считает шлюз.

**Подача материала.** E на 1 мм пути = k · S_филамента / (π·D²/4), где
S_филамента = (d − h)·h + π·h²/4 (сопло d, слой h; если h ≥ d — π·d²/4), D — внутренний
диаметр шприца, k — коэффициент подачи. Быстрый выбор шприцев 3/5/10 мл (8,66 / 12,06 / 14,5 мм).

## Головки

Головки 1–3 — сменные инструменты: на сопле стоит одна, остальные — в манипуляторах или
гомогенизаторах. Где какая головка, шлюз сообщает в телеметрии; карточка головки показывает
«на сопле», «в манипуляторе Л/П», «в гомогенизаторе» или «не установлена». Выдавливать
(ось E платы 1, `num1 M587 I7`) можно только головкой на сопле.
- «Ручное», под каждой головкой — **Задать как текущий** (`main M639 N`).
- «Калибровка», карточка **Инструмент**: текущий инструмент (`M639`), **Взять 1/2/3** (`M620 N`),
  **Отдать текущий** (`M621`). Для смены нужен свободный манипулятор — иначе шлюз откажет.

## Периферия

- **Пневматика** — реле платы 2: насос, стол, крышка, сброс.
- **Гомогенизаторы** — серва уходит при каждом движении ползунка (как в String_line4).
- **Освещение** — `num2 M581 A<0..255> I1` при каждом движении ползунка; значение сохраняется.
- **Лазерная система** — два луча калибровки сопла (плата 1): «замкнут» (1 — луч цел) или
  «разомкнут» (0 — луч перекрыт); ниже — состояние поиска сопла по X Y Z.

## Стол

«Главная → Стол»: **Выдвинуть стол** (`M624 1`) и **Забрать стол** (`M623 1`). Галка
**Подъём крышки** (`M643`): при заборе стол заезжает под захват, крышка снимается и
поднимается; при выдвижении — возвращается. Во время печати стол не двигается.

## 3D-сцена

Вкладка «3D» на экране «Печать»: вращение пальцем, масштаб щипком или кнопками −/+,
виды Изо/Сверху/Спереди/Сбоку, ползунок слоёв, перемещения (холостые ходы) по кнопке.
Во время печати выполненное рисуется ярко, оставшееся — бледно, красный маркер — сопло.
Рисуется без OpenGL, поэтому не зависит от видеокарты.

## Оформление

Фирменный стиль Университета МИСИС: синий #0541F0, голубой #37EBFF (градиент),
тёмно-синий #0A1E64, тёмно-серый #505569, белый. Шрифты по брендбуку: Nekst
(заголовки) и TT Norms Pro (текст), если установлены на компьютере; иначе — Tahoma,
которую брендбук разрешает для цифровых материалов. Все блоки с числами имеют
зарезервированную ширину и не меняют размер при смене значений.

## Экран и масштаб

Интерфейс рассчитан на 1920×1080 логических точек. На 4K с масштабом Windows 150 % места
больше, со 100 % — элементы мелкие: тогда «Консоль → Интерфейс → Масштаб» (75–150 %,
после перезапуска). Если места не хватает, на странице появляется прокрутка — окно не
выходит за край экрана.

## Режимы интерфейса

Переключатель на вкладке «Консоль»:
- **Простой** — для оператора: Главная из трёх шагов (подготовка → программа → печать),
  Печать, Генератор (основные параметры), Ручное, Консоль (только журнал).
- **Расширенный** — все экраны: Периферия, Калибровка, Камеры, телеметрия, ручные команды.
Выбор сохраняется.

## Структура

- `protocol.py` — все команды шлюза и плат и разбор телеметрии `st1`/`st2` (одно место для правок)
- `printer.py` — связь по TCP в фоновом потоке + симулятор шлюза для демо
- `gateway.py` — автозапуск шлюза и окно ожидания подключения; `auth.py` — пароль
- `config.py` — оси головок, подложки и G54, скорости, камеры, материалы, настройки пользователя
- `gcode.py` — отправка без изменений и модель разбора шлюза (превью, прогресс, время)
- `gen.py`, `stl.py` — генератор программ и нарезка STL
- `view3d.py`, `preview.py` — 3D-сцена и послойный вид
- `job.py` — задание печати, прогресс, остаток времени
- `pages/` — экраны, `widgets.py` — сенсорные элементы, `theme.py` — оформление
- `bioprint.spec`, `exe_main.py`, `version_info.txt`, `build_exe.bat`, `make_shortcut.ps1`,
  `shortcut_python.bat` — сборка exe и ярлык на рабочем столе; `assets/icon.*` — значок

## Что нужно уточнить у разработчиков шлюза и прошивки

1. **T той же головки** (`T1`, когда головка 1 на сопле) — шлюз отдаёт головку и падает на
   `AddRange(null)`. Пульт предупреждает перед стартом.
2. **E после T и G54** — шлюз начинает участок с E = 0, но продолжает накопленное E файла:
   программы слайсеров с T получат выброс материала. Генератор это обходит.
3. **Конец участка после скругления** (`convert_frames_v3`, ветка последнего отрезка): если
   в последнем углу участка построена дуга, последний отрезок начинается с вершины угла, а не с
   конца дуги — откат назад до ~0,3 мм. Основной баг `first_p` исправлен в шлюзе 06.10 (`c92a1d9`).
4. Дуги G2/G3 шлюз не выполняет; `G4 P` склеивает числа; в G91 смещение прибавляется по числу слов.
5. Признака «идёт базирование» в телеметрии нет — «Home выполнен» пульт определяет по
   остановке моторов кинематики.
6. `M613` (калибровка дельты) отправляет `main M589 X80` — команда с адресатом `main` не доходит
   до платы.
7. `M642` (выезд стола) только запоминает флаг — шлюз его пока не использует.
8. Температура сопла и рабочей камеры.
